## 1. 独立热点：实现控制与状态闭环

目标流程：普通拍摄状态下，MOD“手机连接”页手动开热点，显示 SSID、密码和 IP；手机加入后访问既有 8781 HTTP。该路径独立于原厂 RVF 等待页。手机仍须通过 Android 正规 WLAN API/系统确认加入网络，不承诺绕过系统权限。

先从原厂脚本和相关 WM 代码确认驱动、网卡、电源、AP、DHCP 的启动/停止顺序、必需参数及配置生成规则。复用底层驱动和原厂组件，新增有限的控制入口，避免复制整套网络管理服务。缺失实机生成配置时，继续从现有镜像/代码提取；仍缺的必填参数必须显式报错，不猜测国家码、信道、供电接口或伪报启动成功。

实现手动开、关、状态查询：

- 默认关闭，不在每次开机新增扫描、常驻轮询或自动热点恢复；菜单同时支持方向键/OK、转盘及大触控目标，沿现有布局接入。
- 以实际接口、进程、地址及服务状态判定结果，区分关闭、启动中、开启、停止中、失败；失败显示具体阶段。
- 幂等与互斥覆盖重复请求、并发开关、启动一半取消、超时和异常退出。只停止本功能拥有的进程/资源，保留真实进程身份检查，不按名字 `killall`。
- 若原厂 RVF/其他无线模式正在使用网卡，明确报告冲突并保留现场，不抢占未知使用者。关闭时只撤回本功能创建的地址、路由和 DHCP/AP 资源。
- 不往原厂固件写入配置；临时配置和敏感信息使用适当权限，日志隐去密码。
- 首版沿用现有 HTTP 能力；独立热点不自动提供原厂遥控视频/拍摄会话，也不悄悄触发 RVF 授权。

## 2. Telnet：独立调试开关

Telnet 使用已建立的网络，不负责创建热点；开启热点也不自动开启 Telnet。菜单放“设置 → 调试”，显示开关、实际监听地址与端口，默认关闭。

选取或编译兼容原厂 ARM/运行库的 Telnet 服务，记录来源、版本、许可证和可重建命令。先验证目标二进制的依赖和实际登录链路，再接脚本与菜单；发行物须包含必要许可证。不要只放一个要求系统已有 `telnetd` 的空壳脚本。

明确认证方案，验证允许与拒绝路径；不以 `-l /bin/sh` 或空密码 root 作为默认远程入口。凭据不硬编码、不写进日志或截图。绑定所选相机网络地址，避免误监听其他接口；没有可用网络时报告原因。

复用现有服务身份与有界控制方式，实现重复开启不生多个服务、关闭只停止自己的服务、PID 复用/端口占用不误杀、停止后监听确实消失。若 Telnet 依赖本功能的热点，热点关闭时一并收尾其 Telnet，不影响其他网络的未知服务。

提供手机终端和电脑 PuTTY 的连接说明，使用运行时显示的相机 IP 与 23 端口。Android Termux 或其他支持 Telnet 的客户端均可；本轮用隔离测试客户端模拟手机连接。

## 3. 模拟验收与性能（不安排上机）

先构建受影响产物，再运行必要的现有测试；为新增网络生命周期使用实际生产控制代码配合隔离命令替身，替身记录调用与模拟失败。原厂驱动/射频行为单列为模拟未覆盖，不因缺设备暂停其他任务。

| 范围 | 本轮必须验证 |
| --- | --- |
| 热点正常流程 | 配置与调用顺序正确；开→状态→关；连续重复无重复 worker；8781 服务继续使用现有入口。 |
| 热点异常流程 | AP/DHCP 分阶段失败、缺参数、无网卡、超时、启动中关闭；清理仅限已取得资源。 |
| 所有权与冲突 | RVF 占用拒绝、未知进程保留、PID 身份变化、已有地址/路由保留、并发请求串行。 |
| Telnet 真实协议 | ARM 服务在私有 VM/隔离网络启动，客户端完成 IAC、认证和有限测试命令；错误凭据被拒；断开后可重连，关闭后端口不可达。 |
| 菜单 | 键盘、转盘与触屏入口一致；状态来自服务结果；失败可见；MENU 可退出，不因后台等待冻结 UI。 |
| 默认与包内容 | 冷启动不自启新服务；缺服务二进制/配置时显式失败；首装、升级清单包含脚本、二进制与许可证，升级保留用户设置。仅生成隔离候选，不改公开附件。 |

性能对照使用同一个私有 VM，记录“新功能均关闭”“热点控制空闲（替身）”“Telnet 空闲”“Telnet 有连接”四组的进程数、RSS、CPU 累计耗时和控制响应时间。可测隔离 HTTP 数据传输，标注其为虚拟网络吞吐。关闭状态检查开机路径是否增加 worker/轮询，避免为新功能退化现有首开速度。

功耗仅分析无线驱动常开、AP 广播、CPU 唤醒和数据传输的开销来源。VM 结果不生成相机耗电、电池续航或省电百分比；热点替身不具备射频功耗或无线吞吐证据。原厂 RVF 与独立热点的实体性能比较留作后续独立任务，本轮不要求设备采样。
