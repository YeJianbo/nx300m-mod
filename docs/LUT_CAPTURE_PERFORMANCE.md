# LUT 成片参数更新开销

2026-11-03。本轮测量的是原厂 `CIpcs3DLutD4::Update`、LUT RAM 适配器和原厂 UDD 写表函数的 CPU 路径。ARM Linux VM 使用真实 NX300M 1.15 IQ／UDD 库，寄存器区域由 RAM 替代。

## 修改

适配器原先每次 Update 都打开、读取、解析、关闭选择文件。现在为每个在途上下文保留独立解析缓存，复用既有的 stat64 身份比较方法。设备、inode、模式、大小、mtime／ctime（含纳秒）任一改变即重新读取；首次读取前后再次核对身份，变化中的记录不缓存。文件删除、格式错误时使用原厂表，后续有效选择可以恢复。

缓存不占用共享锁、不分配堆内存，不改变 196 字节的 loader 配置 ABI、上下文布局或写表函数。选择恢复、预览同步仍在控制操作中执行。每次原厂 Reset、参数更新、三通道写表以及状态发布照常执行。

## 同 VM 对照

每种状态 9 批，每批 256 次 Update；表内是各批平均单次耗时的中位数。每次 Update 前均执行原厂 Reset，使无 Hook 的基线也真正写出三个通道；不能拿被原厂缓存跳过的调用与真实 LUT 写表比较。计时期间关闭跟踪输出，结果文件在计时区间外保存。

| 状态 | 墙钟耗时（ms／次） | 线程 CPU（ms／次） |
| --- | ---: | ---: |
| 原厂，无 Hook，前测 | 0.0162 | 0.0160 |
| 原厂，无 Hook，恢复后 | 0.0158 | 0.0157 |
| 修改前 LUT 100% | 1.8084 | 1.7960 |
| 选择缓存 LUT 100% | 1.6143 | 1.6067 |
| 修改前 LUT 50% | 1.8657 | 1.8540 |
| 选择缓存 LUT 50% | 1.7250 | 1.7164 |
| 选择缓存 LUT 0% | 1.3520 | 1.3413 |

本组 100% 的参数更新开销减少 10.7%，50% 减少 7.5%。相对无 Hook 的前后测均值，当前 100% LUT 增加约 1.60 ms／次。这是模拟环境中的参数提交开销，不能换算成整张照片保存时间；实际一次拍摄调用 Update 的次数也需要实机计时确认。

「关」会恢复原厂调用槽位，属于表中无 Hook 基线。「0%」仍保留适配器，仅在写表时传回原始数据，两者开销不同。

## 检查和证据

- 三通道共 2190 个 16-bit 字均核对；0%、50%、100%、关闭及恢复原厂结果正确。
- 独立 loader VM 检查重复选择命中缓存、同尺寸原地改强度、错误记录、删除与恢复，以及已有表缓存、重新注入和旧版恢复。
- 选择、预览与拍照的整链回归继续使用 MFW 用户态库和现有 Session fixture。它验证资源生命周期和控制结果，实体 ISP 为替身。

本轮 loader 全系统 VM、菜单三组检查、ABI7 Session 整链 VM 均通过并关闭。Session 的 Open／Close 为 206／206，设备 Open／Close 为 48／48，剩余引用为 0；检查包含黑白与彩色切换、拍照后恢复、单独关闭预览、全关和重新加载。参数缓存仍使用 196 字节配置 ABI，当前 Still 构建号为 `1078378604`。更新已写测试卡并完成回读，尚未在实体相机执行。

同 VM 的修改前／后原始结果：`outputs/performance/lut-capture-cost/selection-cache-vm/`。首次现状采样：`outputs/performance/lut-capture-cost/arm-vm/`。首次采样的设备模拟退出 0，分析器曾因引用局部辅助函数报 `AttributeError`（退出 1）；修正后重读保留输出通过，错误报告也已保留。


## 实机缺口

本轮尚未测量实体快门到保存、JPEG 编码、SD 写入或 LCD 有效帧率。最低实机检查是同一场景、固定曝光与照片格式，分别拍「关」、Mono 和一款彩色 LUT，核对颜色、连续拍摄、保存等待及关闭后的恢复。保留取景预览开／关两种条件，才能把预览资源交接与 JPEG／写卡等待区分开。
