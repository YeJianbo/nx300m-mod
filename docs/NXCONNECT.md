用户 2026-10-26 16:56 录屏显示：系统仍处于“正在连接设备”时，App 已结束一次服务识别并提示未找到服务；随后系统提示“已连接”，App 没有再识别。录屏中没有进入遥控页。另一次照片显示 Mod 已连接而机身仍在原厂无线等待页；仅凭照片不能证明原厂配对已完成。

### 原厂等待页的转态依据

下表为 NX300M 1.15 原厂 ELF 虚拟地址的只读分析，属于静态证据，不是实体握手通过记录：

| 原厂位置 | 行为 |
| --- | --- |
| `libdi-network-dlna-stack.so:0x121a30..0x121a88` | RVF 授权分支检查 AllShare mode 为 4 和 `SEC_RVF_` 身份；MobileLink mode 为 2，使用另一身份分支。 |
| 同库 `0x121de4 / 0x121e04` | 手动描述请求通知机身授权界面，然后等待允许／拒绝信号；HTTP 服务连通不能替代授权。 |
| `libdi-network-dlna-rvf.so:0x4bc64..0x4bc70` | `UPnPCDSRVFGetInformation::ResponseRequest` 发出 `0x35`，无需先启动视频流。 |
| `di-camera-app-nx300:0x1fcf4c / 0x1f9f5c` | 将网络事件映射为 UI `0x203`，执行原厂 RVF 界面和状态切换。 |

原厂描述请求可能经通用路径返回 200；仍必须检查 SCPD 和 SOAP，不能将描述成功当作完整配对。原厂视频 URI 路由及 `HandleHeader` 未发现以 RVF 身份头为等待页转态门槛，因此视频 GET 的身份头缺失不是这里已证实的原因。

关闭视频实例可发送 `0x37`，进入包含 RVF 终止与 SoftAP 清理的原厂完成路径，执行取决于机身状态。当前没有已验证的“只隐藏等待页，同时保持 WLAN”独立接口；不能以短暂开闭视频或假确认事件替代。MobileLink 客户端、Samsung Link 自动握手和保持无线的独立机身交接仍未实现。

## 0.20.22 连接等待与遥控阻塞修复

修复自动 WLAN 在已有 IPv4 但缺少后续属性回调时不完成的问题：获批后立即读取地址，必要时每 300ms 补查；系统批准与 DHCP 分别有 65 秒、20 秒等待上限。失败、取消与初始失联清理定时器和 pending 状态；已获批的网络仍由进程保留。连接异常和取消统一结束首页加载，命中服务后停止后续网段探测。建连不再等待目录／缩略图能力自检，首页概览只用 HTTP，不自动 telnet、校时或读取磁盘信息。

进入遥控页不自动发起原厂 RVF，须点击“连接原厂遥控”。配对前停止并排空 Mod 屏幕请求，配对总等待限 60 秒；会话期间阻止 Mod 机身按键、B 门、屏幕切换和保活按键，与原厂 SOAP 分开。取消、失败或视频断流不自动叠加配对。只有原厂 SCPD 声明的动作可用；原厂 NX300M 库没有 HeartBeat 或会话结束 SOAP，客户端不发送虚构动作。退出页面停止自己的视频与 HTTP 请求，临时系统弹窗遮挡页面不立即拆除会话。

## NFC 配对目标与兼容边界

App 配对按“手机靠近相机 NFC → 读取配对信息 → 经 Android 系统批准加入相机 WLAN → 验证相机服务 → 打开相册”实现，无需预先接入路由器。NFC 负责引导，照片与遥控使用 Wi-Fi；这与手机原生 Quick Share 的附近发现和无线通道协商是两个流程。

前台读卡支持在 NXConnect 首页接收 NDEF；有效的标准 Wi-Fi WSC 或 `nxconnect://connect` 凭证才进入配对确认。未知标签不自动认定为 NX300M，不自动启动 WLAN 扫描或转入旧相机相册。连接其他相机时先结束旧连接，重新识别服务。NFC 标签不会被写入。

尚未取得实体 NX300M 的原始 NDEF 记录。原厂存在 NFC 相关组件和事件，NX300 维修手册另有工厂按机型及 MAC 信息写标签的说明；这些材料不能证明 NX300M 标签就是 WSC、可以由手机改写，或能从关机唤醒相机 Wi-Fi。当前标准凭证解析不等于原厂三星标签已经适配。真实标签、手机 NFC、系统 WLAN 连接批准和机身无线启动仍需实体联调。

离线证据：`outputs/deployment/recovery-research/NX300-service-manual.txt:5035–5070` 记载外部 PC 的 NFCWriter.exe 按机型和 MAC 末六位写标签、碰手机启动 camera app；该手册属于 NX300。真实原厂 1.15 的 `smart-wifi-app-nx300` 中，`CAPPNetworkSmartphoneLinkState::handleNetworkEvent`（`0x7b7c8`）的 NFC_STARTED 分支调用 `SetSoftApClientName`（`0x7c750`）、客户端 MAC 比较（`0x7c770`）和 `AcceptMobileApp`（`0x7c814`）；这条分支证明已有手机会话的处理，未证明触碰会主动创建 AP。当前不需要为手机侧读卡修改内核或 bootloader。

## 0.20.11 SRW 镜头信息写入

镜头信息编辑支持 JPEG 和 NX300／NX300M 的 TIFF SRW。单独 RAW 可打开编辑；RAW＋JPEG 编辑同时保存两份独立修改，JPEG 同步或恢复不会清除 SRW 待导出的修改。旧版只存 JPEG 修改的配对照片，在再次编辑或确认下载 RAW 时将旧修改合并到尚无独立记录的 SRW。批量补录仍可选择 JPEG、RAW 或两者下载。

## 统一机身设置

`camera/info.capabilities` 中的 `iso_controls/shutter_limit/dial_lock/color_style/picture_wizard/looks/lut_selection/recipes/recipe_style`
用于协商原生设置。首页在相册／遥控下方提供独立“相机设置”分组，连接且支持设置时启用。
相册菜单、查看器右上齿轮与遥控页“机身设置”共用同一底部设置面板，直接打开“机身”页；
可切换配方、LUT、画面页。面板的原厂 ISO 菜单会进入遥控页并发送 ISO 按键。
没有设置能力时遥控页继续发送原来的 ISO 按键。
打开或重新读取时先刷新当前连接能力，再串行读取支持的组，未读取或无法识别的项不可写。
ISO 的 1 EV 选项提交 `one-stop`；状态回填不会触发开关写入，选择原值不发送请求。
缺失状态的数值显示“未读取”，滑块、开关和选项保持禁用，避免将 UI 默认值当作机身状态。
ISO 单字段 POST 只返回该字段，因此验证写入读回后，再在同一客户端互斥锁内 GET 全部 ISO
设置，更新完整快照；不会把缺省的其余字段误判为不可用。滑块支持拖动结束提交，以及键盘／
无障碍调节停顿后提交，程序回填不提交。

| 设置 | 原生接口与提交方式 |
|---|---|
| ISO／快门 | `/api/v1/exposure/iso`、`/api/v1/exposure/shutter`；只提交本次改变的单项表单字段 |
| 指令拨盘锁 | `/api/v1/controls/dial-lock`；JSON 布尔 `enabled` |
| RGB 通道增益 | `/api/v1/color/rgb`；0–200 整数，100 为中性；提供明确的三通道复位按钮 |
| 原厂画面参数 | `/api/v1/color/picture-wizard`；单字段 JSON 差量，饱和度／锐度／对比度 -4…4，色彩角度 -1…359 |
| LUT 库／选择 | `/api/v1/looks`、`/api/v1/looks/select`、`/api/v1/looks/stock`；从实际部署列表选择或清除选择恢复原厂 |
| 七维配方 | `GET /api/v1/color/recipes`、`GET/POST /api/v1/color/recipe`；按目录 ID 应用完整批次，或提交 `reset:true` 恢复原厂 |

以上请求共用相机客户端的同一个互斥锁，超时 18 秒，网络操作继续使用原有 Wi-Fi binder。
严格 HTTP 方法保留服务端错误正文，不把非 2xx 当成功。选择原值、取消或打开面板均不写入。
拨盘锁和原厂画面参数直接提交本次变化；RGB 原生 API 要求全三通道，因此修改单通道时会
在同一互斥锁内重新读当前三通道、合并本次变化后提交，避免用旧弹窗值覆盖其余通道。
该锁串行化此 Android 客户端的请求，不声明跨其他客户端的原子比较交换。

每次提交都验证目标值读回；RGB 同时核对完整三通道，LUT 核对暂存选择。失败或读回不符
会清除面板快照、禁用所有写入，直到重新读取。连接对象变化时同样禁写。读取某组失败时
该组不保留旧值，其余成功读回的组可用。

RGB 显示原厂预览／拍摄矩阵是否收到、setter 返回和实际修改状态。画面参数显示 IQ 模式、
设置与 IQ 读回是否一致以及当前模式是否启用三项参数。LUT 直接使用同一原生服务，不新增
引擎或浏览器后端；缺 hook 时仍显示实际库与状态并禁止选择。HTTP 202 只表示选择已暂存，
面板区分等待原厂调用和三路转发，提供重新读取；转发不代表已验证 ISP 成像。

七维配方位于同一“机身设置”对话框，不另设遥控入口。显式能力 `recipes` 控制目录浏览，
`recipe_style` 控制机身桥的读取与写入；均缺失的旧机身隐藏该部分。当前服务实读返回
68 项，选择器逐项显示标签及 `R/G/B/H/SAT/SHARP/CONTRAST` 七值，按“应用配方”后才发送
`{"id":"portra400"}` 等批次。独立“恢复原厂七维与额外 RGB 增益”按钮发送 `{"reset":true}`。
界面说明应用会替换当前七维与额外 RGB 增益，状态仅属于当前相机会话。

配方区显示当前七值、代次、是否匹配目录及独立控件覆盖状态，并分别列出预览／拍摄链的
RGB、色相／饱和度、锐度、对比度四阶段。只有对应 mask 为 15 且未 superseded 时该路

0.20.17（65）接入NX300原厂RVF协议：以应用独立持久身份发出`SEC_RVF_`描述请求并等待机身确认，读取ContentDirectory描述和SCPD，再调用`GetInfomation`。原厂描述入口默认7676，尚无SSDP后备发现；控制地址、服务版本和流端口均从响应读取。只在相机声明支持时调用HeartBeat、MULTIAF和Shot，不自动拍摄、不切换原厂模式。页面关闭、用户取消或相机连接改变时结束HTTP和取景。原厂取景按实际RIFF/AVI头选择解码，不把X11的OSD镜像当作传感器画面；实机握手和真实码流尚待验证。

本版最终Release构建成功，APK为7,431,741字节；`StockRvfClientTest`与`RiffVideoReaderTest`各5项，共10项通过。测试使用本地HTTP服务和合成AVI fixture，未验证实体手机MediaCodec或NX300M真实取景流。取消HTTP和释放取景解码器均在后台清理；Shot独立等待最长60秒，保活和对焦继续使用短超时。最小实机检查：相机进入Remote Viewfinder，手机连接8781后打开遥控页，点“连接原厂遥控”，在相机上允许；观察配对、格式识别和真正出帧是否分别成功，随后可用专用测试照片验证一次对焦与拍摄。取景失败时可切换相机屏幕查看机身状态。

0.20.16（64）增加全局连接观察：选定网络丢失时清除相机对象和首页状态；应用在前台时查询相机信息，连续两次无有效响应后显示未连接。主动断开会释放应用申请的WLAN，被动服务失联保留已批准的WLAN以便重试。回到首页会重新接收全局状态。连接帮助补充Samsung Link加入已有WLAN的方式，本机该联网模式尚未实测。

此前版本 0.20.15（63）修正自动发现只查询80端口的问题，优先识别8781并保留实际控制及相册端口。系统批准加入WLAN后，按网关和当前IPv4网段查找相机；服务识别失败不再主动断开WLAN，支持继续查找或手动重试，连接菜单仍可主动断开。
