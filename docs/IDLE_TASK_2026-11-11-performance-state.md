遇到必须实机确认的分支，立即记录现有证据、缺失信息及最小上机步骤，将该分支标记为“待实机验证”，继续其余离线工作；不等待插卡、开机、手机连接或用户回复，不把整轮标记为阻塞。单个 VM/工具失败时，先检查原始错误，限定修复和重试范围；环境仍不可用就记录未验证原因并转做可运行的任务，不反复耗尽三小时。所有离线目标完成即可交付，实机待验单列，不用模拟结果冒充实机通过。

## 1. 缓存回收正确性和耗时（约 55 分钟）

文件：`mod/metol/lut_tune_cache.h`，已有定向入口 `tools/probe_tune_cache_evict.py`。当前问题已用实际回收函数的受控软件夹具复现，证据在验收目录 `cache-evict-findings.json`、`cache-evict-probe.c`、`cache-evict-worker.py`：

- 用 stat 判断目录，随后 opendir/unlink 会跟随 `looks/nx-tune-*` 目录链接，删除目标目录里的文件。夹具只操作本次验收目录里的数据，未触碰真实照片。
- 只收集 64 个旧目录并据此计算剩余量，100 个旧缓存只清到 60；删除失败也直接减少 remaining。
- 目录名只检查前缀，清理内部文件没有限定生成器拥有的文件。

实际修复：只回收契约明确的生成缓存，拒绝跟随链接；异常名称、未知文件和异常目录保留；保护当前 RAM selection、已保存选择以及正在生成/刚生成的目录。不能用“创建一分钟后一定没人读”代替引用保护。统计整个候选集合，删除结果据实际成功情况计数；控制回收计算/内存和一次控制事件中的阻塞成本，不在每帧执行。允许受保护/新鲜目录暂时超过目标数量，但报告不能把它伪装成硬上限已满足。

有针对性地验证：100 个过期普通缓存能清到目标或明确的保护上限；正常/悬空链接、未知文件和异常目录均不被误删；当前应用与保存记录引用的表保留；删除失败不会假报成功；冷启动仍能读到所选表。复用现有引擎隔离夹具，不能只测复制的伪实现。

## 2. 当前 LUT 选择可靠保存与统一读取（约 65 分钟）

文件：`lut_engine_shared.h`、`nxui.c`、`nxui_preview_state.h`、`lut_tune_cache.h`、`mod/deployment/mfw/lut-boot.sh`，以及实际搜到的其他读取入口。

已确认：`nx_lut_persist_selection()` 仍用 O_TRUNC 覆盖 `.state/lut-choice`，失败可清空唯一旧记录；`nx_preview_lut_applied()` 将空文件 EOF 判成已应用，损坏记录使 UI、引擎和恢复链产生不同理解。

采用与现有微调双槽保存一致的可靠策略，复用已有校验、序号、固定文件和成功确认机制，避免在曾有 FAT/exFAT 目录项问题的卡上回到反复 rename 覆盖。复用合理的已有实现，不再建一套平行状态服务。LUT Off 是有效选择；缺失、损坏、有效 Off、有效 LUT 应明确区分。读取旧合法记录时保持兼容；迁移或新记录写入中断时，仍能选择上一份有效记录。UI、CLI、开机恢复与缓存引用保护必须读取同一个有效选择；不能只改 writer 然后让 Shell/UI 继续信任旧兼容镜像。

最小验证：有效旧记录迁移；写新槽短写/中断，旧值可恢复；新槽校验损坏回退；两个槽都损坏时不误报开启；Off 重启仍为 Off；所选 LUT 与强度恢复一致；缺失/空/截断记录不误报已应用；缓存回收保护所有仍需恢复的有效记录。保留 fsync 与错误反馈，不把 RAM 已请求当成持久化成功或硬件已应用。
