# IPCS Session 复用测试卡

这张测试卡默认使用 ABI7 Session 引用复用。连续预览期间，固定线程通过
原厂 Open／Close 保留一个额外引用，减少逐帧重新初始化；每帧的原厂
Open／Close、LUT、YCC、Reset 和 Still IQ 恢复继续执行。
正常预览关闭计时与调用采样。原 ABI4 loader/blob 保留在原位置，
ABI7 文件单独放在 ipcs-diagnostic/。

机身操作：

1. 相机关机、装卡、断开 USB，再开机。长按 Custom 打开面板。
2. 选择「LUT 滤镜」进入滤镜面板，先选 Hard Mono，保留并关闭。长按 Custom，选择「开启取景预览 · 当前 LUT」。
3. 退出面板，先不拍照也不进回放，检查黑白是否直接出现。ABI7 补接了停流完成后的原厂内存匹配与恢复；这一机身表现需要本轮复测。
4. 在 LUT 面板切换 GR Pos 等正式彩色风格，直接退出查看，再拍照核对。开菜单保持预览。「关闭取景预览 · 照片保留」只停取景；再拍照应继续带 LUT，之后切风格也不自动重开预览。
5. 正常使用即可。需要开发端查看日志时，等待写卡灯熄灭后关机，再将测试卡接回电脑。

不需要相机 Shell，也不需要在机身切换版本做对照。模拟器已覆盖普通入口
默认启用复用、关闭采样、连续帧引用保留、拍照排空后恢复及软停释放。
新版本的实际 LCD 帧率和 Open 耗时要由实体取得，模拟器不模拟物理 ISP 时间。

「当前 LUT」读取当前选择；首次开启、尚无 RAM 选择时由现有引擎恢复卡上保存的风格。
在 LUT 面板换风格或强度会同步到已开启的预览，明确选择原样则恢复原样。
本版也修复面板隐藏后等待后台任务时的 CPU 空转。

LUT 列表首项为「关」。它停止预览处理、释放 Session 引用，撤回成片的两个
LUT Hook，并保存关闭选择；再次打开 LUT 列表不会自动加载成片模块。
选回正式风格时按需重新加载，取景预览由「开启取景预览 · 当前 LUT」开启。
软停后由原厂控制线程移除 S2 预览节点，沿用原厂停流、排空和重建流程。
拍照期间延后重建，视频回调只发送非阻塞请求；RAM 映射保留至相机进程退出。

主菜单恢复完整布局，不再默认显示临时测试面板。调试项集中到「调试与诊断」，
包括预览状态、同步、保存诊断、关闭并保存诊断、服务状态和自启设置。
普通关闭不运行诊断导出，保留照片 LUT。

成片 loader、RAM blob、菜单引擎和遥控服务按同一个 Still build 成套部署。
菜单不再提供只改变预览的独立黑白按钮，避免预览与 JPEG 分别选中不同效果。
测试轴和 A/B 副本从目录移除，保留 Hard Mono 和正式风格。
卡上新选择保存为 `.state/lut-choice`，原有 `.state/lut-selection` 只供兼容读取。

## 开发维护采样

`test-monochrome-timing` 命令保留给开发维护：Session=0、计时和调用采样开启。
机身菜单不提供此项，普通预览不启动该任务。

开发端读取 logs/fn-key.log 中的 ipcs_open_call 和 open-export 回执。
每个窗口最多保留 64 次 Open，各段包含 wall/线程 CPU、UDD 返回分支、
设备 Open、映射、IRQ、初始化及 mutex 时间。菜单显示成功和模块已安装
不代表已经取得处理帧；没有记录时按未激活排查。

同一入口还会启动只读 KDD 短采样，自动保存 `ipcs_kdd_window` 和
`ipcs_kdd_call`。它查询原厂 opener 接口的引用数及持有者列表，不启用
Session，也不修改引用计数。接口不可用、没有取景调用或脱离失败时保留
错误记录；不据此宣称内核上电分支已经被直接探测。

`ipcs_kdd_ready` 区分首帧就绪、等待超时和配置已取消；随后
`ipcs_kdd_window.stage` 区分原厂文件、驻留状态、线程、opener 查询和
ptrace 观察阶段。首帧前软停会取消等待，不会为了采样挡住关闭操作。
观察器在同一进程只做一次完整认证，首帧后复查身份和代码，不再在繁忙
取景时重复整库 SHA。等待、采样和退出确认使用各自预算，普通控制命令
的超时不变。

上一版若只因只读观察在 attach 前取消而留下超时标记，本版关闭预览时会
核对原控制进程、相机寿命、线程脱离状态及对应日志，证据匹配后归档标记
并软停；无需删卡文件。其他未解决操作仍保留现场。

仅 persisted=true 代表完整 Open 窗口已经写卡。软停成功与诊断保存分别回执。
完整窗口由开发端分析，正常使用无需运行采样。

启动失败也会自动保存：`NX_PREVIEW_FAILURE` 至 `NX_PREVIEW_FAILURE_END`
包含 loader 原始 stderr、退出码、进程身份和 RAM 路径。代码指纹不符、
GOT 槽位不符和旧 ABI 状态会输出具体差异，不再只保留菜单的通用提示。

UDD 的 `open()` 可由原厂 libc 或 libpthread 的线程取消封装提供。加载器
核验两份原厂库及入口代码，保留实际解析目标；驻留查询、重开和软停沿用
同一目标，不再把 libpthread 入口误判为其他模块占用。

若提示 resident build/ABI 不匹配，旧 RAM 模块仍在运行。不要删除其状态文件
或反复注入。保留提示与日志，开发端按旧 loader 处理旧模块的恢复与接入。

回退由电脑恢复本轮部署备份中的脚本、菜单、runtime-files.list 和重启标记，
移除本轮 IPCS_OPEN_DIAGNOSTIC、IPCS_SESSION_PREVIEW 选择标记。旧后端二进制没有覆盖；切换前
须确认相机旧进程及其驻留模块状态，不能把普通关机等同于模块完全卸载。
