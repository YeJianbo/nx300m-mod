# NX300M 成片 LUT：代码审查与 9³ 编译优化

2026-11-02。本轮优化电脑端编译器，生成候选表；默认仍为 `legacy`。相机 RAM Hook、ISP 设置、运行时处理流程和主 `looks/` 表保持原状。

## 审查结论

当前能改进的是 **9³ 对源 LUT 的保真度**。20 款同源对照中，独立 RGB888 样本的平均 RMSE 从 2.919 降到 2.173，约下降 25.6%。两张照片、40 个风格／场景组合的平均 RMSE 从 1.081 降到 0.716，约下降 33.7%。数值单位均为 8-bit 通道色值。

最重要的未决项是 LUT 在真实 ISP 中的颜色域和插值规则。当前软件评测使用 RGB code／三线性模型；它衡量源函数的近似误差，不能用来确认实机 JPEG 已校色。候选表须在模型确认、实拍对照后启用。

| 优先级 | 代码审查发现 | 处理 |
| --- | --- | --- |
| P0 | `F(factory_node)` 只有在源 LUT 与原生表输出属于同一颜色域时才是正确的色彩组合。原厂接口命名不能证明这个前提 | 保留假设，不替换默认表；先标定 LUT 之后的颜色处理链 |
| P1 | 原 `cube_to_d4.py` 只在 729 个节点采样，未优化节点间的输出误差 | 新增有界全局拟合，使用独立离网格样本评估 |
| P1 | 原厂组合表也只复合节点，未优化整个 `F(interpolate(factory, x))` | 组合表单独拟合这一完整目标；19 款组合表均完成对照 |
| P1 | 原编译器向下取整，存在负向量化偏差 | 增加四舍五入基线和整数节点优化；单独四舍五入的平均 RMSE 收益约 0.5% |
| P1 | 最小均方误差不保证灰阶形状。初版 Tri-X 候选出现最大约 0.32 个 8-bit 色值的灰阶反向 | 加入通用单调黑白形状约束；修复后 8193 点检查反向为 0 |
| P2 | 单纯优化 RGB 误差，未直接优化感知距离 | 增加 RGB＋OKLab 联合拟合实验；额外感知收益约 0.37%，暂不优先于简单全局拟合 |
| P2 | Adobe creative 表不包含完整原厂相机风格与 RAW 显影 | 保留源表已有风格；相机校准与风格制作分开处理 |

## 原生模型核查

静态证据见 `outputs/lut-disassembly.txt` 和 `tools/stock_lut.py`：

- `CIpcs3DLutD4::SetParam`，ELF 地址 `0x33bbd0`，生成三路 9³ 数据，变量循环确定慢轴／中轴／快轴。
- `libudd.so.3.1::ipcs_3d_lut`，`0x955c8`，按通道复制 `0x5b4` 字节，即 730 个 uint16；每路 729 节点加一个 padding。当前使用数值为 0～1023，总表 4380 字节。
- SDK 的 `IPCS_LUT_R/G/B` 及 `RGB3D_LUT_SW` 支持“RGB 3D LUT 模块”这一解释；写表函数本身只有数据传送，没有可核查的像素插值或 Gamma 算法。

因此静态代码确认了格式和通道命名，尚未确认标准 sRGB、线性 RGB、实际节点坐标归一化、三线性／四面体选择、内部舍入及裁剪位置。ARM 模拟器可以核验表字节和调用，却不能补出缺失的 ISP 像素模型。

设 `H` 为原生 LUT 输出到最终 sRGB 的后续处理，目标风格为 `F`。理想组合应为：

```text
T_candidate = H_inverse ◦ F ◦ H ◦ T_stock
```

现有直接组合假设 `H` 可忽略。如果 `H` 包含 Gamma 或颜色矩阵，这个假设可能造成风格强度与色相错误；若含裁剪，逆变换未必存在。继续增加拟合迭代不能修正错误的颜色域。

## 通用编译算法

实现位于 `tools/lut_resample.py`，入口仍是 `tools/cube_to_d4.py`。方法可显式选择：

| 方法 | 用途 |
| --- | --- |
| `legacy` | 原三线性节点采样＋向下取整，默认基线 |
| `round` | 相同节点采样，四舍五入到 10-bit，分离量化影响 |
| `fit` | 有界全局拟合＋源表相对平滑约束＋整数节点优化＋单调黑白形状保持 |
| `fit-perceptual` | 在 `fit` 基础上做完整通道耦合的 RGB＋OKLab 有界 Gauss–Newton 微调，保留 RGB 保真项 |
| `fit-integral` | 用连续体积积分替换随机体积采样；保留相同灰轴、边界、平滑及整数节点优化 |

统一规则：

1. 每款使用相同的 21376 个训练点、权重和 seed `61183`，覆盖全部 8³ 单元、六个外表面、灰轴和原 9³ 节点。照片不参与拟合。
2. 灰轴的目标是**源 LUT 对灰色的真实输出**，保留胶片原有冷暖色调。平滑正则作用于相对源节点值的残差，不向 identity 收缩。
3. 解限制在 0～1；随后量化到 0～1023，并在整数节点空间优化训练目标。求解未收敛会报错。
4. 对本来是单调黑白的源映射，灰轴上的三线性函数可写成逐段三次 Bézier。用加权保序回归约束控制点顺序，再保持整数节点组和，消除灰阶反向。判定来自源数据，不使用风格名。
5. 感知微调采用 RGB 平方误差＋OKLab 平方误差；根据当前输出的完整 3×3 Jacobian 联合优化，不把三个通道敏感度当成完整色差。线搜索及量化后检查使用实际非线性训练目标。

本轮的目标始终为源 LUT **100% 效果**。没有降低预览／成片强度，也没有为 NC、GR 或其他单款写颜色补丁。最终还是相同的 4380 字节表，优化计算全部发生在电脑 CPU。

## 与桌面项目的同源对照

已实际编译和运行：

- `new_nx300m` 的 RGB888→线性 RGB12→18³→RGB888 原 C 像素路径；以及它的可变网格 65³ C 核，外层使用同一套原项目 sRGB 编解码表。
- `nx300-lut` 的原 `lut_load`、`lut_prepare`、`apply_row`。本轮分离像素算法，不运行其拍摄守护进程或 JPEG 二次压缩。

两者均加载本地同一批 20 款 33³ `source.cube`。18³ 烘焙严格遵循原项目的“线性坐标→sRGB 编码→采源表→sRGB 解码→12-bit 量化”；与其原 Python 转换器交叉检查，全部 5832 节点、17496 通道值一致。

统一 RGB888 holdout：16000 个随机颜色＋256 个灰阶，seed `40719`；与训练集独立。每个后端输出统一量化到 RGB888 后比较。

| 后端 | 平均 RGB RMSE | 平均 OKLab 距离×100 | 各款 P95 绝对 RGB 误差均值 |
| --- | ---: | ---: | ---: |
| 原 9³ | 2.919 | 0.4351 | 4.567 |
| 四舍五入 9³ | 2.905 | 0.4298 | 4.517 |
| 全局拟合 9³ | 2.173 | 0.3208 | 3.367 |
| 感知联合拟合 9³ | 2.173 | 0.3196 | 3.350 |
| 连续积分拟合 9³ | 2.153 | 0.3175 | 3.317 |

结论是：9³ 全局拟合改善了当前表；完整源表的桌面处理仍最精确。线性 18³ 在暗部的编码分辨率与 code-domain 9³ 不同，不能仅按节点数判断谁更好。65³ 主机数据不是 NX300M 的原生格式。

### 灰阶、区域和渐变

- 在连续 24000 点 holdout 中，20 款的总体 RGB RMSE、平均 OKLab 距离均优于原编译器；肤色近似区、绿色、蓝色、近灰、阴影、高光六类的区域 RGB RMSE 也均未出现退化。这些区域是统一 RGB 掩码，不是实测色卡。
- 两张照片为街景与室内杯子，先按 ICC 转到 sRGB，再缩到长边 480；没有用于训练。交互页包含原图、源 LUT、原 9³、优化／主机后端四列。
- 源风格方向投影均值从 0.9648 到 0.9839，表示输出沿源表改变方向的分量更接近目标。它不衡量风格是否好看，也不是完整相似度。
- 渐变另外测试灰轴和 12 条色立方体边，每条 1025 点。10 款的局部步长残差 P99 有增加，例如富士 Velvia 从 0.308 到 0.450 个 8-bit 色值。平均颜色误差改善不等于所有局部斜率都更准确。
- 原生表的强对比源效果本来就可能有长平台。Velvia 50 的源灰阶最长平台为 104 个测试点，原 9³ 为 40，拟合后为 97；不能把平台变长一律解释为色阶变差。
- Tri-X 初版的灰阶反向是明确回归，已修复。形状约束改动 17 个节点，最大 3 个 10-bit 数值；修复后的 8193 点灰阶反向为 0，三输出通道保持完全一致。

实机插值还未确认，报告另含三线性／四面体敏感性。所有离线模型都有连续输出的假设；这些结果不能替代真实 ISP 的渐变、舍入或色阶检查。

## SpektraFilm 与校色建议

[SpektraFilm](https://github.com/andreavolpato/spektrafilm) 适合借鉴的是“负片→印相→扫描”的完整风格生成和明确的输入／输出空间。它支持导出单个或多个 LUT；本项目当前适合接收完整烘焙的单个 sRGB→sRGB 3D `.cube`。颗粒、光晕等空间效果不能装进普通 3D LUT。

本轮审查了它的模型与导出接口，**没有运行其光谱模拟或烘焙真实胶片 profile**，所以没有给它虚构一行实测分数。已跑的主机对照是前述两个 C 项目，使用现有 20 款相同源表。

建议下一步先确认真实原生颜色模型，再考虑扩大感知优化：

1. 复用 [原生诊断与最小实拍步骤](LUT_CALIBRATION.md)：固定曝光、白平衡、Picture Wizard，保存 RAW+JPEG；确认 stock、0%、identity 的关系，测试各轴和三通道均值响应。
2. 用已知输入／同阶段输出和混合节点探针区分插值、输入节点坐标及舍入。最终 JPEG 还经过后续色彩处理，不能仅用它的 gamma 反推 LUT 内部 gamma。
3. 原生模型成立后，用固定光源色卡、灰阶、肤色、植物、蓝天做两组比较：原厂输入校准，以及目标风格保真。不要为了让标准色卡更中性而消掉源风格的暖灰、分离色调和对比曲线。
4. 比较同一场景的 legacy／fit／Stock 恢复，核对两种原厂表来源。现有 `fit-camera-look`、RAW/DCP 显影工具可以生成独立参考；它们不能直接确认 ISP 内部色域。

目前优先保留简单 `fit` 候选。额外感知迭代仅改善约 0.37% 的平均 OKLab 距离，而且 RGB RMSE略升；当前更值得解决的是原生模型与源风格完整性。

## 原厂实现与固定 9³ 的剩余空间

2026-11-03 增量结果。原厂图片向导与智能滤镜的逐款选择、表值和调用地址见 [原厂风格逆向](NATIVE_STYLE_REVERSE.md)。它们把矩阵、曲线和其他处理分开，不能仅凭菜单存在就推定使用同一种 3D LUT。

新增 `tools/lut_integral.py`。当源 `.cube` 节点在 0～1 内时，在源网格与 9³ 网格的共同分段上计算精确三线性交叉矩，替换原随机体积项。灰轴、边界、正则项和 10-bit 整数优化不变。输出超出 0～1 的源表，以及原厂表复合后的目标，改用确定性 Gauss 体积求积；这些分支是数值近似。

原 20 款统一算法、100% 风格，未按名称调参：

| 检查 | 上版 fit | fit-integral |
| --- | ---: | ---: |
| RGB888 平均 RMSE | 2.17266 | 2.15288 |
| 平均 OKLab 距离×100 | 0.32081 | 0.31750 |
| 两照片／40 组合平均 RMSE | 0.71642 | 0.71982 |
| 近灰区平均 RGB888 RMSE | 0.51674 | 0.51808 |
| 渐变局部步长残差 P99 均值 | 0.28456 | 0.28636 |
| 富士 NC 的 RGB888 RMSE | 1.40578 | 1.38196 |

总体 RGB888 误差改善 19 款，Hard Mono 从约 0.163 升至 0.165。近灰、肤色、蓝色、阴影、高光存在逐款回退；新方法没有取代 `fit` 候选。照片未用于训练，也没有根据这两张图选择每款的参数。

`tools/evaluate_d4_projection.py` 另求解统一 RGB 体积下的最优值，**只限 RGB-code／三线性模型**：

| 同一精确体积目标 | 20 款 RMSE 均值 |
| --- | ---: |
| 原节点采样 | 2.88616 |
| 上版 fit | 2.12824 |
| fit-integral | 2.10675 |
| 0～1 有界浮点节点最优值 | 2.06594 |
| 允许节点越界的浮点下界 | 1.98832 |

在这个模型内，当前候选到有界最优值只余约 1.9% 的宏平均 RMSE 空间。该差值还包含灰轴／边界保护和正则的取舍，不能全归于 10-bit 量化；更不能把它当成真实 ISP 的误差下限。继续增加同类拟合迭代无法消掉大部分剩余误差。

数学核对通过：非单位 DOMAIN 的独立 101376 点分段求积，交叉矩最大差 `4.6e-18`，源能量差 `2.9e-15`；仿射投影节点差 `1.8e-15`；identity 与原厂组合逐字一致。完整记录为 `projection-limits.json`。

新增 Lightroom 来源构成单独的 60 款扩充批次，见 [Lightroom 风格扩充](LIGHTROOM_LUT_LIBRARY.md) 和 `outputs/looks/lightroom-import/`；上述 20 款数字保留为原批次。
