## 2. 本轮目标与不变边界

先处理当前无线入口卡死，再修 LUT 编辑状态与持久化，随后补已有底层功能的菜单及配置接线，最后按测量结果优化 UI 和状态发布。泛绿修复涉及尚未确认的硬件并发，单独推进，不与菜单修复混成一次部署。

**最新补充 · P0：用户原话“手机直接连接根本连不上，然后相机进了界面关不了机了，卡住了”。这同时涉及手机连接失败与机身关机被阻塞，优先于 R1–R3、新增功能和性能优化。具体进入的是原厂无线/Remote 还是 MOD 连接界面尚未确认；根因未定位，不预设为 App 网络绑定或 Session 问题。现有 LUT 正常取景反馈不覆盖这个无线入口故障。**

- 保留 SmartFilter + IPCS 原生 9³、10-bit 路线，不退回 IPCM CCM/Gamma/YCC 近似拟合。
- 不改 RAW、不删除原厂 Reset、Still IQ 恢复或拍照仲裁，不为了理论 FPS 跨帧持有通道锁。Session 不列为本轮预设故障；只有新回归证据才进入相关代码。
- 不改 LCD DMA、不写未知寄存器，不添加 CPU 逐帧图像处理。
- 不整体替换 IPC，不合并全部 Shim，不大改已正常工作的菜单架构。
- 复杂设置继续放 NXConnect，相机端执行、快速选择和必要开关即可；暂不做视频增强、LUT 混合、JPEG 质量修改。
- 正常 LUT 取景的既有反馈保留，不反复要求用户证明“能用”。无线入口卡死是本轮新增的明确故障，需要单独修复；新功能的物理曝光、功耗、校色等独立指标也没有自动完成验收。

## 3. 已核查的 Review 问题：首先实现

以下结论来自本轮直接读取当前源码，不是只接受外部 Review 的描述。

### R1 · P1：切换风格或分类覆盖未保存微调

位置：`mod/metol/nxui_lut_panel.h` 的 `lut_set_category()`、`lut_step()`、`lut_load_tune()`；`mod/metol/nxui.c` 的 `choose()`、`lut_has_changes()`。

事实：`choose()` 切换索引后重新从磁盘加载微调，未先保存该款编辑状态。分类、上下款、列表、转盘等都会进入相关选择路径。目前 `lut_has_changes()` 只将当前全局编辑值与一次 origin 快照比较，不能代表多个风格的草稿。

实现要求：

- 分开表示浏览选中项、每款编辑草稿、已持久化配置和最近成功提交。以稳定 `look_id` 关联，不能仅依赖会随目录重排改变的行号。
- 每款只缓存小型参数草稿、强度和必要标志；不要为所有 LUT 常驻缓存整张表。按需加载，保留分类浏览性能。
- 切换风格、分类、收藏筛选、列表/微调视图均不隐式丢弃草稿，也不隐式提交其他风格到相机。
- Fn 从微调返回列表，仍按用户要求保存当前款并留在面板；OK/顶部保存成功后回取景器。返回/关闭时覆盖所有尚未处理的草稿，保存、放弃、继续编辑的作用范围必须明确。
- 不把“未提交到机身”与“修改尚未写盘”混成一个 dirty 位；浏览到另一款本身不等于那一款参数被改动。

最低回归：NC 微调后切宾得再回 NC，值保留；两款各自编辑不串值；Fn 保存只影响当前款；退出选择放弃时按明确范围清理草稿。

### R2 · P1：微调与收藏非原子持久化

位置：`mod/metol/lut_tune_cache.h::nx_tune_save()`；`mod/metol/nxui_lut_panel.h::lut_toggle_favorite()`。

事实：两处都直接对正式文件 `O_TRUNC`，写失败会破坏旧内容。参考实现是 `mod/metol/nxui_prefs.h::nx_ui_pref_write()`，但它在 UI 编译单元内，不能直接从 LUT 引擎调用，也不能不经检查照搬固定临时文件名的并发假设。

实现要求：

- 抽取适合实际调用者的轻量原子写辅助，保持原文件格式兼容：同目录临时文件 → 完整写入 → fsync/close → rename → fsync 目录。
- 正确处理短写、EINTR、失败清理、路径长度和同目录临时文件冲突；保留现有路径/符号链接约束。写入最终 SD 数据根，不能误写短命 RAM 服务副本。
- rename 前失败必须保留旧正式文件；rename 后目录同步失败应如实报告持久化未确认，不误称旧内容已回滚。
- 收藏成功后才更新 UI 的已保存状态；失败时保留可重试的编辑值，不能把截断后的空文件再读回当成正常收藏列表。
- 不改变已经以私有目录生成后再发布的 LUT 表缓存，不额外逐帧 fsync。

最低回归：正常保存/重新读取；一次受控写入失败仍保留旧微调与收藏；重复保存兼容旧文件。复用现有 probe，不扩展为大规模故障注入框架。

### R3 · P1：提交索引与参数未一同快照

位置：`mod/metol/nxui.c::confirm_lut()`、`start_child()`、`exec_lut_engine()`、子进程完成后的 origin 回写；`nxui_lut_panel.h` 的触屏和导航入口。

事实：队列保存风格索引，执行时用全局 `lut_strength` / `lut_tune.value[]` 组装参数。`lut_key()` 多数路径检查 `commit_requested`，但 `lut_step()`、分类和微调等入口没有统一覆盖。风险窗口在确认与 fork 启动之间；fork 后子进程已有独立地址空间，不能将问题误述为子进程持续读父进程变化的内存。

实现要求：

- 确认时复制不可变请求：`look_id + strength + tune[7] + request_generation + 退出/留页意图`；待执行和在途请求各自持有自己的快照。
- `exec_lut_engine()` 只使用该请求，完成回写也只认可该请求，不能用完成时的当前编辑值宣称另一组参数已生效。
- 同一风格、不同微调不是同一任务。不能继续仅靠 `queue.running == selected` 判断可以复用在途提交。
- 统一按钮、触屏手势、滚轮、Fn 和方向键的忙碌处理。即使选择锁定漏了一条路径，也不能发生 A 风格配 B 参数。
- 关闭 LUT 作为明确请求处理，不被旧的成功回调重新开启；失败保留草稿和正确的错误状态。配置保存成功不等于 LCD 像素效果已验证。

最低回归：同批事件确认 A 后立即切 B；同一款强度/微调发生变化；失败重试；关闭 LUT；Fn 留页与 OK 退出。检查后端记录的完整 argv 及完成回写，而不只断言 UI 索引。

### R4 · P2：Still Hook 重复发布状态，先量调用再改

位置：`runtime/lut_ram_blob.c::nx_lut_ram_ipcs()`、`publish()`。

事实：`forwarded == 7` 时无条件格式化 JSON、写临时文件并 rename；当前没有内容去重。它位于 `/var/run`，不是 SD 写入。现有选择文件和表身份缓存应保留。代码能确认重复发布机制，不能确认自然调用频率、实际耗时，更不能据此认定每个预览帧都触发整套 Still Hook。

实施顺序：

1. 在已有 ARM 调用链夹具中记录 Update、完整三通道、publish 次数及成本，区分模拟调用频率和实体自然频率。
2. 有收益证据后仅去重状态发布；保留所有必要的原厂三通道写表、错误状态、重新注入后的首次发布和状态文件丢失后的恢复。
3. 先检查 `lut_live_loader`、控制脚本是否依赖文件更新/代次作为确认，保证去重不会让控制请求永远等不到响应。
4. blob 有多 TID 固定上下文；按槽缓存不等于全局状态没有被另一线程覆盖。明确并发发布顺序，不能为去重在原厂调用外加跨硬件事务大锁。

没有实机自然频率时，标为待测优化，不报“每帧节约 N ms”。不要为这项清理改变 blob ABI 或连带修改 Session。

### R5 · P2：连续输入绘制合并，保留单次按键响应

位置：`mod/metol/nxui.c` 的事件批处理、`next_frame` 调度；`mod/metol/nxui_ximage.h`。

现状：已有字形缓存、变化区域 XImage 上传和单窗口复用，但 CPU 仍完整光栅化。现有调度使用 `now_ms()+33`，不代表实测可达 30FPS。历史同一 ARM guest 操作帧 P50 为 94.5→62.5ms、P95 为 120→93ms，不能当作实体 LCD 延迟。

先比较连续拖动时约 15Hz、合并中间状态只绘制最新状态的方案；全部输入仍需处理，最后一次值必须显示。单次按键、退出和保存不统一延迟到慢刷新周期。保留无输入等待、Expose 重绘与在途任务进度。未测到收益不默认切换，不先做复杂脏区域光栅化重构。

### 无线故障：下一位 Agent 的定位入口

**本轮明确症状：手机直接连接根本连不上；相机进入相关界面后卡住，关机无响应。** “界面”的精确入口未确认，不写成已经定位的 Remote Viewfinder 故障。历史上另有 App 内连接但实际访问失败的反馈，不能用历史症状覆盖这次更严重的机身卡死。

先取证相机端：保留现有卡内日志、当前菜单/服务/无线补丁版本与入口动作，区分卡在进入界面、启热点、客户端握手还是退出/关机等待。检查连接动作是否在 UI 线程同步等待 shell/服务、是否已有 remote 实例/锁未释放，以及拍照/媒体暂停、预览让路和关机取消是否完整配对。这些只是待查候选，不是已确认根因；不能为了“能关机”跳过原厂资源释放或强杀相机 app。

离线/ARM 可模拟服务不返回、启动失败、取消与退出的状态回归，确认有界等待和失败可退出；无法模拟的真实无线驱动阻塞明确列出。不得用模拟器通过就宣称物理关机恢复正常。后续最小实机验证必须包含：进连接页 → 连接失败可返回 → 退出后原厂拍照正常 → 正常关机，不只验收传图。当前卡死路径在取证前不要求用户反复尝试。

按真实失败层逐一缩小范围，优先利用现有日志与 App 诊断，不让用户反复在相机上操作或打开 shell：

1. **加入 WLAN**：记录系统授权/选网回调、目标 SSID、Network 获得/丢失与超时。`WifiNetworkSpecifier` 的 App 专用网络与系统默认网络不是同一个概念；不能仅凭 Wi-Fi 图标或 `onAvailable` 判定端到端已连接。
2. **实际路由**：核对发现、能力查询、相册列表、缩略图和原图下载是否一致使用所选相机 Network 的 socket/client；排除移动数据、VPN、旧 Network 回调和 stale client。不能只给其中一个 HTTP 客户端绑网，就宣称全部链路已修复。
3. **服务发现**：从 DHCP/网关与现有发现逻辑确认实际地址，区分原厂服务和 MOD `8781`，记录 HTTP 状态/连接错误。`8782` 是电脑模拟器代理入口，不能当成手机连接实体相机的默认端口；不要把旧地址硬编码成所有场景通用。
4. **相机工作模式/服务生命周期**：确认热点及 remote 服务在普通拍摄、回放、原厂 Remote Viewfinder、休眠前后分别是否可用。若原厂无线模式本身会切换画面，需要查清对应生命周期；不能用手机端跳到相册掩盖机身仍被锁在监视器的问题。
5. **重连与界面状态**：网络切换/断开后清理旧回调和连接，仅在身份/能力请求成功后显示已连接；相册/传图失败须可恢复，不无限扫描或假显示成功。

相关源码：`mod/nxconnect/NXConnect/app/src/main/java/com/nxwa/nxconnect/net/` 下的 `CameraWifi.kt`、`NetworkBinder.kt`、`CameraDiscovery.kt`、`CameraConnectionMonitor.kt`，以及 `ui/CameraPairing.kt`；相机端查现有 `mod/metol/remote/` 与 MFW 服务脚本。具体修复沿用现有网络/服务机制，不新增一套常驻代理。

验收至少覆盖：扫描选择并授权 → 确认相机身份 → 相册/缩略图/一张原图传输 → 普通拍摄后新图可获取 → 断开重连。没有实体手机/相机时先完成可验证的软件修复与构建，列出剩余的最小物理验证；不把 Android 模拟器或电脑 HTTP 测试当作无线已修复。NFC 不应成为普通 Wi-Fi 可用的前置条件。

### LUT 编译与照片对比的续接

- `tools/cube_to_d4.py` 的 CLI 和 `convert()` 当前默认已是 `fit`，支持 `legacy`；低层 `compile_cube()` 默认仍为 legacy，所有调用点需要显式审计。不要再次把“切换 CLI 默认”为 fit 当成尚未完成的主任务。
- 用 `tools/probe_lut_fit_workflow.py`、`tools/lut_build_contract.py` 及既有报告核对正式构建是否显式选算法；电脑旧 DCP/LR 库不因格式转换自动成为可公开再分发的资产。
- 颜色域/插值仍是需实拍确认的模型假设。`fit-perceptual`、`fit-integral` 为实验选项，不因某张图更好就替换全部正式风格。
- 用户还要求过 CC、NC、NN、宾得银盐漂白、海盐晴蓝的 JPEG 与 SRW 显影对照；配对按用户给定的 **SRW 编号顺序**，不要只按聊天中附件显示顺序猜测。若已有最终对照图，直接引用；未交付则从 `pic/` 核对后补做，保留原图与 RAW，不作为 R1–R3 的前置依赖。

## 5. 必须保持的菜单交互

- 横向 800×480、三星风格、大字大触摸目标；五主入口 LUT/镜头/曝光/手机/设置，无多余转场。
- “关闭 LUT”明显且独立，表示关闭预览和成片 LUT；“LUT 实时预览”独立控制，可关预览保留 JPEG 风格。
- 顶部分组支持方向键/滚轮；列表上下逐项，只有第一项再按上进入分组，分组下或 OK 回列表，不能跳回旧行为。
- Fn 列表↔微调；从微调返回时保存并留在面板；OK/保存成功显示应用过程后回取景器，失败留页。不要恢复重复的“应用取景”按钮或依赖半按快门才生效。
- 微调上下选项、左右/滚轮调值；既支持按键也支持触摸；MENU 返回，未保存草稿按明确规则处理。

- 保留“原图微调”与彻底关闭 LUT 的区别；参考图是样图，不冒充传感器画面。现有人像/风景/夜景、按住原图对比已存在，不重复开发。
- 收藏/品牌/分类记忆保留；只按需加载图表和调整，不为显示全部风格而常驻所有 LUT。开机恢复现有已保存偏好，不能要求先打开 LUT 面板。
