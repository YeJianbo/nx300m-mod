## 动画 RAM 候选（已构建，未运行验证、未写卡）

新增 `runtime/settings_animation_blob.c`、`runtime/settings_animation.c` 和 `tools/build_settings_animation.py`。不是加载整个旧 firmware-mod：新 helper 只处理动画两个入口和自身 8 KB 匿名映射，不包含旧 V0、曝光、IPCS 或硬件预览控制。原厂程序文件及 libc 在暂停前验证；暂停所有线程后重新核对进程、映射及完整函数字节，使用现有纯 syscall 后端分配 RAM 和刷新指令缓存，不借任意线程执行 dlopen/C 函数。入口前两条指令必须是已核对的独立 A32 prologue；线程恰在这八字节内则拒绝本次修改，返回 4 供重试。

三种模式为：0 调用原厂完整入口；1 仅抑制本次 DrawModeDial 创建的计时器，保留原厂绘制对象并补齐末帧；2 停动画并清除模式拨盘显示。DrawModeDial 先取模式快照，计时器使用该次绘制的快照，避免切换偏好时卡在半次绘制。模式 0 保留小块映射，避免旧回调尚在栈上时释放代码；正常切换复用同一映射。所有依赖函数都来自原厂 1.15 字节证据，未知修改直接拒绝。

`settings_animation.arm status [PID]` 只读核对实际入口、匿名代码及配置，返回 `PID mode installed`；`settings_animation.arm 0/1/2 [PID]` 请求对应模式。省略 PID 时只接受唯一的 `/usr/bin/di-camera-app-nx300`。变更使用 tmpfs 内互斥锁和恢复 worker；超时不能杀死仍持有追踪状态的 worker。菜单仅进入系统设置时做一次状态查询，修改仍走现有后台动作队列。`animation-restore.sh` 只重放明确保存的偏好，有限重试，无常驻轮询。

## 当前上机方案：不刷机的 X11 模式拨盘锁

后续按用户要求重新实现了独立 X11 控制器，不使用旧 V0 注入器、曝光补丁或旧 ELF。依据原厂 `usr/etc/X11/Xmodmap` 的 `!Mode dial` 段，只控制 67–76（F1–F10）。光圈/快门拨轮 185/186、后转盘 113/114、方向键、OK、MENU 均不修改。

`mod/metol/mode_dial_x11.c` 是一次性进程：开启时先核对原映射，把完整原符号保存到 X server 的根窗口属性，再屏蔽十个模式键；关闭时恢复并读回核对。原映射与 X server 同寿命，无轮询守护进程。`status` 直接读键盘映射，不把偏好值当作已生效；无法确认时返回错误。该程序不打开相机进程内存、不调用 AE，不写 rootfs、固件或快照。它不保证其他 RAM 注入方式的行为，也没有复用它们。

菜单“顶部模式拨盘锁定”已接到这个独立后端，并保存 `.state/fw-mode-lock`。启动服务异步执行 `mode-dial-restore.sh`，从源 SD 读取偏好。模式动画、Auto ISO 扩展仍保留为各自待接入任务，本轮拨盘锁的通过不能当作它们已经可用。
