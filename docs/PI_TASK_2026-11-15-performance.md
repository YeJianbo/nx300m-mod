# Pi 性能优化与上轮交付收尾

用户授权：继续优化 NX300M MOD，交给 Pi 执行。全程离线，不连接相机、不写卡、不刷固件、不推送或发布。

## 工作方式

- 在当前权威工作区原位执行；根目录没有 Git，不用发布镜像或临时克隆代替。遵守当前 AGENTS.md。
- 不是独占工作区，保留其他人的修改。先查看现有任务及最新文件；若有同一文件的活跃写入，先协调，不覆盖、不同时运行私有 VM。
- Python 统一 `D:/conda/envs/nx300m-mod/python.exe -X utf8`；PowerShell 使用 UTF-8。ARM 构建需要时将 `D:/Program Files/LLVM/bin;C:/Windows/System32` 加到 PATH 前面。
- 私有 ARM VM 串行；挂载必须隔离 mount/PID 等命名空间，禁止在共享 WSL 挂载 `/var/run`。保留原始失败日志，回收自己启动的 VM；不要留下多份数百 MB、可重新生成的 initramfs。
- 先编译受影响代码，再跑对应的现有必要检查；已有有效结果复用。针对具体缺陷才增加回归，不堆与任务无关的报告或测试。

## 当前必须保留的基线

最新连续拍摄交接修复：`outputs/review/2026-11-14-capture-overlap/final/report.json`，后端 ABI7 / build `345225401`；相册回归见相邻 `playback-regression/report.json`。

原厂调用方不检查 B2Y Open 的返回值。修复让 750 ms drain 超时后仍由原厂生命周期锁完成交接，已持有 native lease 的 Prepare 不因单纯保留电源引用而被拒绝。专项覆盖两拍重叠、四阶段延迟、保留引用、释放计数及故障保护；设备端连续快门卡死仍待新版实机复测。

本任务不修改 `runtime/smartfilter_ram.c`、`runtime/smartfilter_session.inc`、`runtime/ipcs_session.c`、`runtime/smartfilter_ipcs.c` 的生产行为；保留 Reset、Still IQ、Session、拍照仲裁、RAW 和 LCD DMA。发现这些位置的新问题时记录调用链和证据，交回主线程。不要恢复菜单实时取景，不禁用相册 Custom 入口，不以拦截第二次快门掩盖问题。

## 依次执行

1. **先核验上轮实际交付，补齐可离线验收的缺口。**
   - 读取 `docs/NIGHT_TASK_2026-11-13-performance-25hz.md`、`docs/AGENT_WORKLOG_2026-11-13-performance-25hz.md` 和 `outputs/review/2026-11-13-performance-25hz/result.json`。
   - 上轮汇总有“总通过”与单项未验证、敏感性失败日志混在一起的情况。按实际源码、最终二进制及原始日志核对；不要照抄汇总。旧 Pi 网关任务 `227ff3d1-277e-4aea-9c5f-a96d3f73eeef` 状态 unknown，不能据此声称已结束；原生线程 `pi-dd400942-3340-4c24-95d5-5e85b6db51fe`。
   - 无线页面三种输入、Telnet 会话清理、上传故障、worker 回收等已有修复只补必要的缺失证据或确实发现的问题，不全面重写。

2. **优先优化切换 LUT 和连续转盘的实际响应。**
   - 核对 `nxui.c`、`nxui_lut_panel.h`、`nxui_ximage.h`、`lut_table_cache.h` 的当前实现。目标调度 25 Hz 不等于实际 25 FPS；前次记录的 VM 帧间隔 P50 约 82 ms，先从原始日志复核。
   - 采用同一 VM、同一输入序列比较修改前后：事件处理、绘制、参考图生成、XImage 上传分别计时；报告 CPU、帧间隔 P50/P95、最长无绘制间隔、末次输入到最终画面延迟。
   - 依据测量选择局部优化：避免只改参数时重复绘制静态区域，消除绘制中的重复文件读取，复用已有 LUT/参考图缓存，合并过时的参考图生成请求。已实现且有效的缓存不要重复开发。
   - 保证转盘最终数值完整、持续输入中有中间帧、停止后及时显示终值，离散按键/触屏及时响应；Fn 只保存当前款并留在菜单，OK 保存应用后回取景，MENU 按原有语义返回。
   - 浏览/微调不逐次提交 IPCS；保持当前参考图，不更换用户素材，不增加动画或设置项来掩盖延迟。

3. **定位开机后等待面板可用的剩余关键路径。**
   - 将原厂窗口出现、快捷键 ready、服务 ready、面板首帧分开计时。复核已有 BOOT-KEY 快速重试，不把已经完成的优化重复列为待做。
   - 找实际串行依赖、重复检查和冷读，能局部优化且有证据再修改；不通过提前注入、不必要服务常驻或削弱文件校验换取数字。
   - VM 可证软件等待，实机耗时单列待测，不把调度目标、启动夹具时延写成实体性能。

4. **有剩余工作能力再研究 Still Hook 热路径。**
   - `runtime/lut_ram_blob.c` 仍在通道完成时发布状态；先审查统计和状态写入频率，区分夹具频率与原厂自然调用频率。
   - 本轮不盲目开启去重，不改原厂 LUT 写表。不足以决定生产优化时，给出具体测量入口和缺失证据即可。
