## 第一优先：LUT 总开关与独立预览偏好

必须分别表示 LUT 是否应用、用户保存的预览偏好、实际预览后端状态。关闭 LUT 停止效果但不改变预览偏好，重新应用 LUT 时按偏好恢复。只有用户单独设置预览开关才改变偏好。

| 操作 | 必须保持的结果 |
| --- | --- |
| LUT 开、预览开，关闭 LUT | 回到原厂路径，偏好仍开；UI 表示随 LUT 暂停。 |
| 再开 LUT | 原偏好开则恢复预览，关则只应用成片。 |
| 单独关闭预览，再切换/关开 LUT | 始终保留偏好关。 |
| LUT 关闭时单独改预览开关 | 只存偏好，不启动无效硬件处理。 |
| 开机 stock 分支或恢复失败 | 不把保存的偏好擅自改成关；区分暂挂、恢复中、成功和失败。 |
| 强度为零 | 不据此改写 LUT 与预览两个开关。 |
| Fn 保存当前款 | 只保存当前预设，不应用、不退出，其他款草稿保留。 |
| OK 保存并应用 | 使用不可变的请求快照，成功后回取景。 |

已静态确认的入口：

- `mod/metol/lut_engine.c`：`disable` 调 `nx_lut_stock()`、`service_control("smartfilter-preview.sh", "stop", 1)`；`boot` 的 stock 分支也写预览偏好零。
- 当前部署 wrapper 的源码是 **`mod/deployment/mfw/smartfilter-live-preview.sh`**；不要改成同目录旧探针版 `smartfilter-preview.sh`。live wrapper 的 `stop|restore` 调 `save-preview 0`，把运行时停止误当成用户关闭偏好。
- `mod/metol/lut_engine_shared.h`：`nx_lut_sync_preview()` 仅在 RAM backend marker 仍为 smartfilter 时同步，缺 marker 后不能按偏好重开。
- `mod/metol/nxui_preview_state.h`：缺少“LUT 关闭，预览暂挂”的状态语义。
- 注意 selection lock：engine 持锁时 wrapper `enable-s2` 又调 engine `activate`，不能直接递归调用形成锁死。查清锁序后修生命周期，不能采用关前保存旧值、关后强行写回掩盖错误。
