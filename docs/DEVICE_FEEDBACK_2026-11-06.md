## 尚未解决

### 菜单超时息屏

原厂 UI 电源定时器由原厂事件处理路径重置，独立菜单取得焦点后不能假设该路径仍收到输入。静态确认：

- `UI_Set_Power_Timer(true)` 停止原厂 0x28、0x29、0x2c 定时器；false 从用户设置 0x390／0x391 重建定时器。
- `UI_Set_Power_Manager_Time_Info(true)` 还调用 `pm_lock_state(0,0,0)` 和 `pm_set_trigger(0)`。
- 本机 `libpmapi.so.1.2` 发送 `/tmp/pm_sock` 数据报。`power_manager::pmControlEventHandler` 的加锁分支按进程加入锁，未看到消费消息中 timeout 字段的路径。不能把带 timeout 的加锁调用当作已验证的有限租约，直接使用可能留下长期锁。

静态记录保存在 `pm/`。尚未改动息屏逻辑；不应以 `XResetScreenSaver` 或模拟按键替代原厂定时器契约验证。下一步应通过原厂主循环中的合法活动入口重置计时，只针对实际菜单输入，并验证退出／进程异常时不影响自动关机。

### 扩展功能启动接入

当前卡是独立 SD 服务链，不能加载原厂进程内的 `camera_firmware_mod.so`、`exposure_controls.so` 等。因此拨盘锁、动画、Auto ISO 等已有实现不能凭菜单项或配置文件声称已经接入实体。

现有合法 preload 接入位于 `mod/deployment/app-loader/preload-persistent.sh`，只对下一次原厂 app exec 生效，依赖机内 `/usr/lib/nx300m-mod` 安装；旧休眠映像不会自动更新。需要核实实体启动路径和可恢复安装，处理两个 Custom 入口的冲突后再启用。当前没有通过仅写卡完成这一条件，未改实体 rootfs 或休眠快照。

### 拍照闪彩色

代码中拍照会先排空预览、让出 IPCS，回退路径复制原始 Y／UV，因此它是闪彩色的候选来源，仍缺少本次实机逐帧对应证据。不得据此认定所有闪色都来自这条路径。

未修改缓冲区所有权、拍照仲裁、Session、Reset、Still IQ 或 LCD DMA。保留上一张处理帧需要先证明缓冲生命周期与模式／尺寸变化时的失效规则，目前没有可直接部署的修复。

## 最小上机复核

1. 插卡开机后打开 LUT：高亮应是当前实际款；若关闭，应显示关闭，列表第一款不冒充已选。
2. 列表第一项按上到分类，再按上到顶部；左右或转盘选预览／关闭 LUT，焦点应有边框，OK 与触摸行为一致，下键回分类。
3. 进入微调改亮度，按 Fn：回列表，相机效果不应用，菜单不退出。切到别款再回来或重启后再打开，已存参数仍在；预设与实际效果不同时显示待应用。
4. 按 OK：应用当前效果，成功后回取景。重启后恢复最后一次 OK 应用的效果，再次开菜单，当前款及分类可见。Fn 未应用的预设不会被当成开机应用命令。
5. 在预览已开启时正常关机、取下再装回电池、开机；无需先拍照或进入相册。若立即开菜单，应显示待恢复／恢复中，随后自动变成开；恢复期间点开关不得关闭预览。若始终未恢复，保留卡上新 `LUT_BOOT` 日志，不能将控制回执当作 LCD 已生效。

息屏、实体扩展加载、拍照闪色继续按未关闭项记录，本次菜单软件检查不代替这些实体结果。
