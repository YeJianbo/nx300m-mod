# 当前功能问题与处理顺序（2026-11-07）

## LUT 与预览的交互规则

LUT 总开关、预览偏好和实际硬件状态应分别记录。关闭 LUT 应停止效果，但不修改用户单独设置的预览偏好；重新应用 LUT 时，按该偏好恢复。偏好为开而恢复失败时，应明确显示失败，不能冒充已开启，也不能自动改成关。

| 用户操作 | 应有结果 |
| --- | --- |
| LUT 开、预览开 → 关闭 LUT | 原厂取景和成片恢复；预览偏好仍为开，界面显示随 LUT 暂停。 |
| 重新选择并按 OK 应用 LUT | 原预览偏好为开则恢复预览，为关则只应用成片。 |
| 单独关闭预览 | 保存预览偏好为关；以后切换、关闭/开启 LUT 均保持关。 |
| LUT 关闭时单独设置预览 | 只改偏好，等应用 LUT 后生效，不为关闭的 LUT 启动硬件处理。 |
| 重启或拔电池后开机 | 恢复最后已应用的 LUT 与独立预览偏好；恢复中显示进度状态，失败可重试。 |
| Fn 保存微调 | 保存当前款预设，不应用、不退出；OK 才保存并应用后回取景。 |
| 强度设为 0 | 输出中性效果，不应据此改写两个开关。 |

**现代码尚不符合上述全部规则。** 已静态确认：`lut_engine disable` 调 `smartfilter-preview.sh stop`，wrapper 随后执行 `save-preview 0`；`boot` 的原厂分支也会写 0。`nx_lut_sync_preview()` 则只在 RAM backend marker 仍为 smartfilter 时同步，关闭后不会依据已保存偏好重开。UI `nx_preview_state()` 在无 backend marker、偏好为 1 时又只能报告待恢复/未恢复，缺少“LUT 关闭，预览暂挂”状态。本轮发布完整性修补未改变这组语义。

下一项应统一这四处状态处理，避免仅保存一份旧值后覆盖回去，也避免由 UI 显示推测硬件已生效。保留现有 Session、Reset、Still IQ、拍照仲裁和恢复 guard。
