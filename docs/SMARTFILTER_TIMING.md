# S2 三组分段计时诊断版（ABI3）

**这是定位卡顿的实验包，不是性能修复版。2026-11-01 的 ABI2 S2 首轮实机验收未通过。**

已观察到取景严重迟滞、黑白直到快门后才出现、拍摄后长时间全屏/写卡。本诊断版保持原有渲染、资源仲裁和恢复顺序，只增加有界 RAM 记录及一次性导出。不会因计时超限强停硬件，也没有通过跳帧、降低强度、删除 IQ 恢复来掩盖问题。

## 安装与退出边界

- 独立包：`nx300m-smartfilter-s2-timing.zip`。旧 `nx300m-smartfilter-s2-preview.zip` 保留，不用旧测试报告给新字节背书。
- ABI3 loader/blob 必须配套；拒绝与旧 ABI2 驻留混用。**安装前正常关机、重启相机进程，不能只重载 MOD 服务。** 不删除 `/var/run` state 绕过版本检查。
- 模块仍为 S2 七槽；S1 五槽只作为回归保留，不先安装 S1 再热切换 S2。
- 不改原厂代码段、固件、RAW Bayer、风格库或开机自动注入。JPEG LUT hook 本版不改。
- 仍为软停：关闭 LUT 和新节点插入，保留已有节点完成回调所需路由、透传和工作区。完全退出需正常关机重启。
- 本次开发仅本地构建、VM 和打包；写卡须另行授权，先备份、读回核验并检查 FAT dirty 位。

## 三组对照

保持同一普通照片路径、画质、画幅、单张模式、曝光/场景和帧几何；记录实际设置，不从文件配对反推用户选择。

| 组 | 机身操作 | 实际路径 |
|---|---|---|
| 节点透传 | 启用 S2 · RAW 预览 | strength=0，S2 节点照常回调，CPU copy + 输出 Flush，无 IPCS 渲染 |
| 单位 LUT | 单位表测试 | identity 100%，完整 IPCS 初始化、处理、恢复，不优化成透传 |
| 实际 LUT | 黑白测试，或跟随当前 LUT | 实际表 100%，与单位表同一调用链 |

每次成功配置开启新记录窗口，最多128个 frame/初始化记录、16个拍摄包装记录，另有时钟校准。满槽仅停止详细记录，节点继续原有处理；drop 数标明窗口容量限制。诊断 scope 每窗口最多32个不同线程，耗尽只丢诊断，不改变业务。

### 建议上机顺序（部署授权之后）

1. 干净启动，原厂智能滤镜保持关闭。进入 **取景预览 → 启用 S2 · RAW 预览**。
2. 先看接管证据：Create/worker 与 `s2_frames` 是否增长。`profile=1`、`enabled=true` 只表示已武装，不证明当前路径存在。若尚未接管，可按原实验协议正常回放再返回；不要为了激活反复按快门、强制调用原厂重建或重复注入。仍为零则停止，并记录“未运行”。
3. 每组提交后退出面板，留3–5秒无状态轮询的观察窗口；不要在窗口内拍摄或切换视频、Wide、放大、连拍及真实原厂滤镜。
4. 在机身写卡指示完全结束后，打开菜单选择 **导出 S2 诊断 · 写卡结束后**。导出冻结当前诊断窗口，不停止取景业务。界面只返回简短回执，不输出全部逐帧数组。
5. 确认“已保存到 Fn 日志”后再进入下一组。单位组如严重迟滞，不继续堆叠黑白/实际组或额外拍摄。
6. 拍摄仲裁验证另作为安全稳定后的单张试验，不自动触发快门。写卡仍活动时不拔卡、不强制断电。

切换 LUT 后仍不变色，先检查是否尚未创建节点；本版记录激活时序，但不承诺已经修复自然重建时机。

## 记录的阶段

所有数值是 `CLOCK_MONOTONIC` 的**调用 wall time**，含调度和等待，不是 CPU 独占时间或纯硬件时间。

- preview 同步包装总时间、effect 总时间；初始化/代次同步单列。
- 准入结果及原因，四次非阻塞 trywait，解锁归还。
- geometry、open、ADE init、R/G/B LUT 参数区复制、输入 Flush、YCC 包装器、输出 Flush。
- Reset、Still IQ initialize、Still IQ process、close。
- 透传 CPU copy、输出 Flush。
- 拍摄 Prepare 等待 backend 排空、原厂 Prepare、原厂 Finish。它们不是完整照片保存/磁盘写入时间。
- 时钟校准、时钟失效、pending 阶段、错误、fault、控制 epoch、几何和选择代次。

解释边界：
- ADE init 内部含 `ipcs_init` 和 Tone/矩阵设置；这里测完整包装器，不单独拆其内部硬件复位。
- 原厂 `ipcs_3d_lut` 每通道复制1460字节到 UDD 参数区，三通道4380字节；不是独立完整硬件上传时间。
- YCC 包含配置、tile等待和收尾；原厂包装器还可能覆盖底层等待错误。返回0不是 tile成功的独立证明。
- Still IQ 恢复可能进入现有成片 LUT hook，重新读 selection/表并写 RAM 状态；是否触发、是否物理读SD及耗时须实测。
- `captures/backend_active=0` 不证明原厂全部写卡完成，也不证明资源恢复成功。错误标志另行保留。
- 不用 busy 比例或 hook 到达间隔推算传感器/屏幕 FPS，不把低帧率的表观果冻直接解释为 sensor 参数改变。

## 导出与完整性

帧路径的新增诊断数据只写固定 RAM，不分配、不 printf、不读写文件、不等待诊断锁。诊断关闭/时钟失败/容量满不改变硬件调用顺序和返回值。

用户显式导出时，loader 复用进程身份和驻留校验，全线程停止期间只冻结诊断准入并复制有界快照；**确认 detach 后**才编码、计算校验和、生成 tmpfs frozen 文件。即使某调用仍 pending，也能复制其当前阶段，不等它返回。

- 原始 frozen：`/var/run/nx300m-sf-diag-<pid>-<start>-<build>-<window>.ndjson`，配有整文件 SHA256。
- 机身可保存到 `/mnt/mmc/nx300m-mod/logs/fn-key.log`；只在当前没有 MOD capture/backend/inflight 活动时追加。仍需用户确认写卡灯已灭、期间不再按快门。
- 若界面提示“仅 RAM，尚未写卡”，**关机后不会出现在卡里**。先等拍摄/处理完成，再重试同一窗口导出。不得将未持久化当成功。
- BEGIN/END、dump ID、序号、记录数、字节数及payload SHA256可检测缺失、截断、交错、冲突。损坏 frozen 文件拒绝追加。
- 成功追加后 fsync 并读回核对；同一 frozen 再次导出只核对已写范围并返回回执。失败保留 RAM 数据，不能保证失败/断电边界的跨文件事务完全原子；离线解析会拒绝不完整证据。
- 常规“预览状态”只输出短摘要；它也会暂停线程，不能在测量窗口反复轮询。
- 每次控制停止记录同时间域区间并推进 epoch；跨控制的样本、时间重叠样本和恢复首帧剔除。窗口有遗漏控制证据时不输出可信稳态分位数。

## 本地分析

正常关机并取卡后，把 Fn 日志复制到电脑，再运行仓库工具（路径改为实际副本）：

```bash
python -I tools/analyze_smartfilter_timing.py fn-key.log --entry-interval --json timing-report.json --markdown timing-report.md
```

解析器验证 schema/build/BEGIN/END/seq/bytes/SHA256，按进程、window、代次、几何和路径分组，区分冷帧/稳态、busy、回退、失败和未完成。输出样本数、p50/p90/p95/max，不把不同阶段p95相加。只有1个样本时分位数没有统计稳定性，不应用于优化决策。

`--entry-interval` 额外按 TID/epoch 隔离，统计相邻合格记录 reserve begin 的入口间隔；不是精确节点队列延迟，也不换算屏幕或传感器 FPS。首帧不作端点，pending/失败/控制污染/配置改变会切断配对；有 dropped 时保守拒绝生成间隔。该指标样本数独立，可能为0，不用阶段耗时补值。

VM 导出明确 `measurement_source="vm"`，相机导出为 `camera`；后者只是导出方声明，不是独立硬件验证。**VM时间绝不能当作相机实测性能。**

## 本版不做的优化

保留 capture lease、backend admission 双检查、同序信号量、cache所有权交接和完整恢复。没有跨帧持锁，没有删除 Reset/IQ，也没有黑白/彩色交替跳帧。

优先研究已验证表字节的 CPU 缓存：完整选择身份、direct/stock3d变体、原厂source与文件更新契约都要纳入失效条件；不能仅凭 LUT generation 缓存共享硬件状态。先根据本版阶段计时确定瓶颈，再决定是否实现复用。

| 对象 | 修改者与失效边界 | 当前结论 |
|---|---|---|
| CPU 中已校验的原始表字节 | 选择身份、路径、文件内容/更新契约、direct/stock3d 变体、进程/root 改变 | 优先候选；本版未加缓存，不能只以 generation 判断内容未变 |
| 与原厂 source 混合后的表 | 原厂 source、强度、选择代次等改变 | 不直接跨事务沿用；已有 `nx_sf_select` 代次缓存不算本版新增优化 |
| UDD 参数区 | ADE 初始化、逐通道写入、Reset/其他使用者 | generation 不代表参数仍有效；保留每次完整提交 |
| IPCS 硬件配置 | open/init/reset/close、拍摄、几何及其他 IPCS 使用者 | 四个信号量的全局覆盖未证明；不跨帧持锁或缓存硬件状态 |
| Still IQ 参数与节点状态 | IQ initialize/process、原厂 Update、拍摄及 JPEG LUT hook | 保留完整恢复；即使外层返回0，也不能独立证明底层所有等待成功 |

若 IQ 阶段占主导，下一候选是缓存 JPEG hook 已验证的原始表字节，仍按当次 source 混合、逐通道提交并归还资源；不是跳过 IQ Process。需要可靠的文件更新与损坏回退契约后才能实施。
